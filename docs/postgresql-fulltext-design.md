# PostgreSQL 中文全文检索设计

日期：2026-11-15。范围：后端，不修改 frontend。

## 推荐方案：后端 Jieba 分词 + PostgreSQL 全文检索

当前服务器没有 zhparser/pg_jieba。后端使用固定版本 Jieba 的搜索模式处理文档、精确模式处理查询，复用相同词典与规范化规则，避免“数据库”查询因 OR 展开“数据”误召回“数据报表”。保留英文标识符及数字、规范大小写。分词结果作为空格分隔的 search_text，与原文本、向量在同一个 INSERT 事务中写入 vector_chunks。

数据库通过生成列 to_tsvector('simple', search_text) 保存 search_vector，以 GIN 索引加速 @@ 查询，以 ts_rank_cd 排序。查询使用绑定参数构造 OR tsquery，保持原有至少命中一个查询词的召回语义。collection、kb_id、未发布文档排除条件在 Top-K 前生效。混合检索继续使用 RRF 和现有重排接口。

增加版本迁移，为已有块统一分词并回填，不重新生成 embedding。删除文本块即删除其全文索引项。重启或其他进程新增、删除后，查询在提交后直接看到数据库状态，不维护内存词表或应用级索引缓存。

保留 KeywordIndex 端口以兼容入库流程，但 PostgreSQL 实现的 rebuild 不再复制全量语料或变更数据库；索引维护只发生在文本块写入/删除事务。验证覆盖中文短语、英文/数字、知识库隔离、旧数据回填、不同连接及实际子进程写入后的可见性、回滚与删除。

取舍：ts_rank_cd 与原 BM25 分数不同，RRF 只使用名次而不依赖分数尺度；中文切词由应用负责，绕过应用直接写 SQL 必须同步提供 search_text。首次迁移需要扫描已有文本，迁移期间暂停写入。

## 备选：服务器中文分词扩展

在 PostgreSQL 主机安装 zhparser 或 pg_jieba，由数据库执行中文切词。可覆盖直接 SQL 修改，但增加服务器依赖和 Windows 部署成本；当前未安装，需要单独完成扩展部署。

## 不采用

继续使用内存 BM25 或中文单字拆分：分别不能满足数据库全文检索及中文词语检索要求。
