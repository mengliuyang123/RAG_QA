# Spec Delta

## Purpose

规定文档入库时如何从原文中提取章节结构（标题路径），以及如何把文档切成“父块（生成上下文单位）+ 子块（检索单位）”两级结构，使每个可检索的文本块都带有它所属章节的信息。

## ADDED Requirements

### Requirement: 提取文档标题路径
系统 SHALL 在解析文档时为每段正文记录标题路径，即从文档最外层标题到该段所属最内层标题的有序列表。只能依据文档自身的结构标记识别标题，不得根据字号、加粗等版面特征推测。

#### Scenario: Markdown 多级标题
- **WHEN** 上传的 Markdown 文档包含 `# 报销制度`、其下的 `## 差旅费`，以及 `## 差旅费` 下的一段正文
- **THEN** 这段正文的标题路径为 `["报销制度", "差旅费"]`

#### Scenario: 同级标题切换
- **WHEN** Markdown 文档在 `## 差旅费` 之后出现 `## 招待费`
- **THEN** `## 招待费` 之后的正文的标题路径为 `["报销制度", "招待费"]`，不再包含“差旅费”

#### Scenario: 代码块中的井号行
- **WHEN** Markdown 的围栏代码块内有一行以 `#` 开头
- **THEN** 这一行被当作正文，不改变标题路径

#### Scenario: Word 标题样式
- **WHEN** Word 文档的段落使用内置样式“标题 1”或“Heading 2”
- **THEN** 该段落按对应级别进入标题路径，其后的正文继承该路径

#### Scenario: PowerPoint 幻灯片标题
- **WHEN** PowerPoint 幻灯片含有标题占位符
- **THEN** 该幻灯片正文的标题路径为 `[幻灯片标题]`

#### Scenario: 无结构标记的文档
- **WHEN** 上传的是 PDF、TXT，或没有任何标题的 Markdown / Word 文档
- **THEN** 标题路径为空列表，入库照常成功

### Requirement: 父块按章节边界切分
系统 SHALL 把文档切成父块：父块不得跨越标题路径不同的两段正文，单个父块的正文不得超过配置的父块字数上限（`PARENT_CHUNK_SIZE`，默认 1500）。有页码的文档，父块还不得跨页。

#### Scenario: 短章节成为一个父块
- **WHEN** 某个章节的正文为 800 字，父块上限为 1500
- **THEN** 该章节恰好形成一个父块

#### Scenario: 长章节拆成多个父块
- **WHEN** 某个章节的正文为 4000 字，父块上限为 1500
- **THEN** 该章节被拆成至少 3 个父块，每个都不超过 1500 字，且标题路径相同

#### Scenario: 章节边界不合并
- **WHEN** 两个相邻章节各只有 100 字
- **THEN** 它们形成两个不同的父块，不合并成一个

### Requirement: 子块在父块内部切分
系统 SHALL 在每个父块内部切出子块作为检索单位：子块不得超过配置的子块字数上限（`CHUNK_SIZE`，默认 500），同一父块下的子块按顺序拼接后，除切分处的空白字符外，必须与父块正文一致（子块之间不重叠、不丢字）。

#### Scenario: 子块拼回父块
- **WHEN** 一个 1400 字的父块被切成若干子块
- **THEN** 每个子块不超过 500 字，忽略空白字符后，按序拼接的结果与父块正文逐字相同

#### Scenario: 父块小于子块上限
- **WHEN** 父块只有 300 字
- **THEN** 该父块只有一个子块，内容与父块相同

### Requirement: 子块携带结构元数据
系统 SHALL 为每个子块保存所属父块的序号和标题路径。子块序号在整篇文档内从 0 开始连续编号，与现在的编号规则一致。

#### Scenario: 同一父块的子块
- **WHEN** 一个父块被切成 3 个子块
- **THEN** 这 3 个子块的父块序号相同、标题路径相同，子块序号连续

#### Scenario: 文本块浏览接口
- **WHEN** 用户在“浏览知识库”中查看某篇新入库文档的文本块
- **THEN** 每个文本块显示的正文是子块原文，不含标题前缀

### Requirement: 索引文本带结构前缀
系统 SHALL 在为子块生成向量和关键词索引时，使用“文件名 › 标题路径”前缀加子块正文作为索引文本；标题路径为空时只加文件名。子块的展示正文和引用原文不得包含该前缀。

#### Scenario: 标题词可以被检索到
- **WHEN** 某子块正文是“标准为每晚 500 元”，标题路径为 `["报销制度", "差旅费", "住宿"]`，用户提问“差旅住宿报销标准”
- **THEN** 该子块可以通过“差旅”“住宿”这些只出现在标题里的词被关键词检索命中

#### Scenario: 引用原文不含前缀
- **WHEN** 上述子块作为引用展示给用户
- **THEN** 引用里的原文是“标准为每晚 500 元”，不带文件名和标题

### Requirement: 兼容旧格式文本块
系统 SHALL 正常检索、浏览和引用没有父块与标题元数据的旧文本块，把每个旧文本块视为只包含自身的父块，不需要停机迁移或强制重新入库。

#### Scenario: 新旧文档混合检索
- **WHEN** 知识库里同时有本次改动前入库的文档和改动后入库的文档
- **THEN** 两类文档都能被检索和引用，旧文档的上下文就是命中的那个文本块本身

### Requirement: 按新规则重新入库现有文档
系统 SHALL 提供管理员命令行工具，用已保存的源文件把指定知识库或全部知识库中的现有文档按新的分块规则重新入库。在每篇文档的新版本发布前，它的旧版本必须照常可检索。

#### Scenario: 重新入库期间可以提问
- **WHEN** 管理员对某知识库执行重新入库，某篇文档正在重新处理
- **THEN** 用户提问时仍能检索到这篇文档的旧版本，新版本发布后旧版本才被替换

#### Scenario: 源文件缺失
- **WHEN** 某篇文档的源文件已不在本地存储中
- **THEN** 该文档被跳过并在命令输出中列出，其他文档继续处理，旧版本保持不变

#### Scenario: 试运行
- **WHEN** 管理员使用试运行选项执行命令
- **THEN** 命令只列出将要重新入库的文档数量和名称，不提交任何入库任务，不产生模型调用
